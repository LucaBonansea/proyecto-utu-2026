## Temas Tratados

1. **Clasificación de reclamos:** Se definió que el **Administrativo** será el encargado de clasificar cada reclamo y asignarlo al área correspondiente. Además, este rol actuará como moderador dentro del sistema.

2. **Visualización por áreas:** Se acordó que los usuarios pertenecientes a cada área únicamente visualizarán los reclamos previamente clasificados para su sector, utilizando un filtro específico.

3. **Administración de clasificaciones:** Se estableció que tanto el **Administrador** como el **Administrativo** podrán crear nuevas clasificaciones de reclamos cuando sea necesario.

4. **Gestión de proveedores:** Se definió que el **Administrativo** será responsable de registrar los proveedores en el sistema, aunque algunos podrán encontrarse precargados desde la implementación inicial.

5. **Registro de usuarios:** Se acordó utilizar el **número telefónico o el correo electrónico** como identificador único (PK) para el registro de usuarios.

6. **Revisión de requerimientos:** Se decidió eliminar el concepto de categorías dentro del sistema, ya que la clasificación será realizada posteriormente por el Administrativo.

---

## Acuerdos

* No será necesario desarrollar las interfaces de usuario que se estaban diseñando inicialmente para los distintos tipos de acceso.
* Todos los usuarios iniciarán sesión desde una única página de inicio de sesión (**Login**).
* La interfaz destinada a los proveedores será sencilla, mostrando únicamente los reclamos correspondientes a las áreas con las que se encuentran asociados.
* Toda la información obtenida durante la reunión fue incorporada al **Project Charter**, al documento de **Épicas** y al documento de **Requerimientos**, quedando la documentación actualizada para la primera entrega.
